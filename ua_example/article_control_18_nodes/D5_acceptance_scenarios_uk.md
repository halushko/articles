# Сценарії приймальної перевірки процесної моделі

- **Ідентифікатор документа:** D5
- **Призначення:** перевірка 21 переходу та цілісності split-join-регіонів
- **Правило приймання:** фактичний маршрут має відповідати дозволеному

Сценарії перевіряють структуру контрольного графа, а не інтерфейс продукту.
Вони охоплюють обидві діагностичні гілки, скорочені маршрути та неуспішне
відновлення з ескалацією.

| ID | Сценарій | Очікуваний маршрут | Очікуваний результат |
|---|---|---|---|
| T1 | Локальна помилка IAM | v1 → v2 → v3 → v4 → v5 → v6 → v7 → v9 → v14 → v15 → v17 → v18 | Доступ відновлено без зовнішнього IdP |
| T2 | Недоступність зовнішнього IdP | v1 → v2 → v3 → v4 → v5 → v6 → v7 → v8 → v9 → v14 → v15 → v17 → v18 | Федерацію перевірено, доступ відновлено |
| T3 | Локальна несправність застосунку | v1 → v2 → v3 → v4 → v5 → v10 → v11 → v13 → v14 → v15 → v17 → v18 | Застосунок відновлено без окремої перевірки залежностей |
| T4 | Несправність залежності | v1 → v2 → v3 → v4 → v5 → v10 → v11 → v12 → v13 → v14 → v15 → v17 → v18 | Залежність визначено, платформу відновлено |
| T5 | Неуспішне відновлення | v1 → v2 → v3 → v4 → v5 → v10 → v11 → v12 → v13 → v14 → v15 → v16 → v17 → v18 | Ескалацію зареєстровано, користувача повідомлено, інцидент закрито з посиланням на ескалацію |

## Критерії приймання

- Кожна гілка після v5 завершується переходом до v14.
- Сценарій не змішує частини різних діагностичних гілок.
- Після v15 вибирається успішний результат або шлях через ескалацію.
- Скорочення v7 → v9 дозволене лише для підтвердженої локальної помилки IAM.
- Скорочення v11 → v13 дозволене лише для підтвердженої локальної помилки застосунку.
