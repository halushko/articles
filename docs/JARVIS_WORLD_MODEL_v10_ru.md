# JARVIS: реальная архитектура памяти (проверяемый этап 1)

## Что было сломано

Начиная с v0.8 документация обещала единую память, но обработка запроса
фактически зависела от переключателя эксперимента. В `hybrid` gateway сначала
проверял старый *классификатор команд* `/resolve`, затем вызывал совершенно
изолированный `/chat` с одним текущим сообщением. Поэтому Qwen не видел
ни имя Димы, ни сохранённую тему, ни возможность поиска. Это не проблема
«необученной модели», а потеря данных между службами.

Одновременно данные о мире уже **хранились** в разных таблицах:
`world_entities/world_facts/world_lessons` с подтверждениями,
`graph_nodes/graph_edges` — производное представление,
`actors` — профиль выбранного говорящего,
`research_turns` — исторические разговоры,
`dialogue_frames` — текущая тема,
`runtime_capabilities` — реальные возможности.
Однако прочитанные реплики прошлых сессий не возвращались как опыт,
а для обычного вопроса `/analyze` просил 3B Qwen построить большой JSON
с уроками, правками, инструментами и ответом одновременно.

## Исправленная граница

```text
Сообщение + actor_id + session_id
       |
       v
  Policy: доступные команды, согласия, запрет действий без исполнителя
       |
       v
  WorldMemory (ОДНА read-модель поверх существующей SQLite)
    |-- подтверждённые сущности и факты с источниками (truth)
    |-- собственная идентичность и выбранный говорящий (identity)
    |-- текущая сессия и provenance предыдущего ответа (working context)
    |-- слова пользователя из прошлых сессий (unverified experiences)
    |-- правила поведения и оценки (preferences / feedback)
    '-- реестр реально существующих исполнителей (capabilities)
       |
       +-- подтверждённый прямой ответ SQLite -> ответ, 0 токенов Qwen
       +-- явный web.search -> политика ask/auto/off -> реальный инструмент
       +-- обычная беседа -> компактный /grounded-chat с памятью и историей
       '-- явно обучающая реплика -> /analyze -> proposal -> review -> world_facts
```

`hybrid` и `apprentice` теперь используют **тот же контур памяти,
диалога, безопасности и поиска**, когда запрос не был принят старым
индексом как изученная команда. `research_only` оставлен контрольным
старым индексом команд, `llm_only` — намеренно изолированный Qwen.
Отличия между ними нужны для измеримого A/B, а не для существования
нескольких «личностей» JARVIS.

В `WorldMemory` нет новой копии `world_facts`. Он собирает
контекст из существующих таблиц; ни миграция, ни очистка данных не нужны.

## Что такое опыт, а что — знание

- **Подтверждённый факт**: принятая запись `world_facts` или профиль
  `actors` с указанным происхождением. Может быть основанием ответа.
- **Эпизод**: прежде произнесённое утверждение выбранного человека
  в `research_turns.question`. Доступен между сессиями *этого* профиля
  при совпадении темы. Помечен `verified=false`.
- **Ответ Qwen**: не попадает в эпизодическое знание и не обновляет граф.
- **Утверждение о выполнении действия**: только результат отдельного
  реально вызванного сервиса, а не слова Qwen.
- **Голос/устройство/выбранный профиль**: пока лишь подсказка, не
  аутентификация и не разрешение на физические операции.

Это **не** означает, что SQLite автоматически «поняла весь мир».
Мир JARVIS будет состоять из подтверждённых локальных фактов,
свидетельств, эпизодов и общего знания языковой модели. Надо проверять
происхождение и противоречия, а не пытаться сохранять каждое предложение
Qwen как новую истину.

## Почему обычные вопросы теперь проще

`/grounded-chat` получает короткую инструкцию и ограниченную
структуру памяти; он не извлекает 5 видов предложений на обучение
при каждом вопросе. Большой структурированный `/analyze` остаётся
для обучения, изменения знаний и сложных запросов.
Модель qwen2.5:3b всё ещё может ошибаться. Изменение уменьшает объём
ненужных задач, но не гарантирует качество ответов.

В экспортируемом `.md` есть `debug_trace` с событиями:
`/resolve` (если `hybrid`), `/apprentice/context`,
`/grounded-chat`, `prompt_trace.memory_injected=true`,
источником истории, числом эпизодов и provenance предыдущего ответа.
Полные системные промпты и секреты в трассу не копируются.

## Критерии готовности, а не обещания

Проверяются автоматически без запущенной Qwen:
1. `hybrid` отвечает на подтверждённое имя через SQLite, не вызывая Qwen.
2. `hybrid` и `apprentice` получают один и тот же контекст и web policy.
3. `llm_only` не читает SQLite (контрольная группа).
4. Утверждение из другого диалога находится у того же actor_id, не
   подмешивается Наде и не превращается в подтверждённый факт.
5. Происхождение последнего ответа берётся из реального server journal.
6. Краткий поиск по контексту не выдумывает тему; если нет темы,
   спрашивает уточнение.
7. Сохранённые диалоги, проверки инструментов, журнал и старые данные
   остаются совместимыми.

**Не проверено автоматически**: реальное качество и скорость
Qwen на Raspberry Pi, распознавание голоса, многопользовательская
аутентификация, семантическое обобщение длинного опыта, самостоятельное
формирование и разрешение противоречивых гипотез. Пока они не измерены
на живом диалоге, нельзя заявлять, что JARVIS «научился понимать мир».

## Как использовать

После `git switch llm-index && git pull origin llm-index`:
`docker compose pull && docker compose up -d`.
НЕ выполняйте `docker compose down -v`.

Проверьте в `Index → LLM`: «Как меня зовут», «Какие инструменты для
замены люстры», «Откуда информация», «Поищи в интернете» и передайте
экспорт `.md`. Для проверок опыта добавьте **новую сессию** и спросите
об утверждении из предыдущей; для проверки границы — переключите actor_id.

Следующий этап имеет смысл только после такого испытания. Он должен
быть посвящён **консолидации пользовательского опыта** (явное
подтверждение гипотез, исправление/отзыв фактов, поиск противоречий,
семантический recall и измерение качества), а не набору новых
регулярных выражений для отдельных предметов.
