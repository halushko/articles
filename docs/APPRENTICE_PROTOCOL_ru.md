# JARVIS Apprentice v0.4: экспериментальный протокол

## Вопрос

Может ли небольшая фиксированная языковая модель приобретать *прикладные*
знания из естественного диалога с учителем через внешнюю подтверждаемую память,
не теряя способности отвечать на посторонние вопросы?

**Это гипотеза для проверки, не утверждение о научной новизне.**

## v0.4.2 — проверяемый граф знаний и маршрутизация памяти

**Исправление протокола:** до этого базовая Qwen отвечала на вопросы об
SQLite, не получая из неё данных. Это порождало ложное «у меня нет сущностей».
Теперь в режиме «Ученик» запросы на перечисление сущностей, отношения и
простые вопросы о владении направляются к подтверждённому графу SQLite
без LLM-генерации. Старые Hybrid и Research-only тоже могут читать граф
для точных запросов к памяти. **LLM-only по-прежнему не видит SQLite: это
экспериментальный контроль**, а не неисправность памяти.

Граф — воспроизводимая **проекция**, не скрытый второй источник правды.
Исходные `world_entities` и `world_facts` остаются нетронутыми для
аудита и отзыва подтверждения. `graph_nodes` хранят постоянные ID
канонических названий (нормализованных без учёта старого `domain`),
`graph_edges` — только подтверждённые тройки, связанные по
`source_fact_id`. Статус `pending` не входит в граф. Подтверждённый
источник можно отозвать: соответствующее ребро исчезнет после следующего
перестроения; если другие подтверждения поддерживают объект, он останется.
Синонимы из `world_aliases` применяются для поиска, но **не склеивают
разные сущности автоматически**. Отдельная таблица `graph_equivalences`
позволяет учителю **явно и обратимо** объединить разные написания
одного объекта, сохраняя все исходные подтверждения и запись в журнале.
Никаких LLM-автоматических объединений по созвучию нет. Одинаковые
написания могут быть омонимами: объединение по написанию — измеримое
ограничение, а не полноценная entity disambiguation.

Поиск для LLM получил ближайшие подтверждённые узлы и рёбра
(`memory.graph`), а также сводные счётчики. Для узкого класса вопросов
(сущности, связи, домашнее владение, обзор памяти) Research даёт
**детерминированный ответ + retrieval_trace + source_fact_id**.
Это не универсальное понимание намерений; более сложные вопросы всё ещё
идут в Qwen. Отсутствие подтверждённой связи не означает, что объекта
нет в реальном мире.

Появился отдельный *контролируемый грамматический baseline* для простых
утверждений вроде «У меня есть X» или «У меня X на Y». Он предлагает
`user — имеет → X`, а `X — на → Y` оставляет исходное неопределённое
отношение «на», не выдумывая «использует»/«питается»/«расположен» до
исправления учителем. Он работает совместно с извлечением Qwen.
Кандидаты **не подтверждаются автоматически**, учитель может
исправить *субъект, предикат, объект*, а не только заголовок.
Поддержка русскоязычных структур ограничена; ошибки разбираются отдельно
по источнику extraction (грамматика или LLM), подтверждению и retrieval.
Ни один из этапов не выдаёт доступ к внешнему API.

### Проверяемые инварианты

1. До обучения и до подтверждения кандидат не влияет на ответ о
   подтверждённых связях.
2. После подтверждения «user — имеет → X» вопросы «Что у меня дома?»
   и «Что у меня есть дома?» должны найти X без совпадения слов
   «дома» и «X».
3. Два старых подтверждения одного написания в разных доменах дают
   один канонический узел с двумя источниками; старые записи не удаляются.
4. Правка тройки перед подтверждением меняет истинные данные рёбер,
   а не только отображаемое описание.
5. Отзыв подтверждённой связи убирает её из ответов и графа;
   журнал обучения остаётся.
6. `llm_only` не обращается к Research (честный экспериментальный контроль).
7. Чтение знаний не исполняет HTTP-запросов и не меняет физические устройства.

### Как измерять

Сравнивай в одной предметной области до обучения, после показа кандидатов,
после подтверждения и после отзыва. Отдельно измеряй: точность извлечения
тройки учителя, долю правок, точность канонизации имён, полноту retrieval,
фактическую правильность ответов, ложные утверждения о действиях, задержку
и число токенов. Подбирай независимые `teach` и `paraphrase` фразы
**до теста**. Нельзя считать успешный SQL lookup доказательством,
что нейросеть приобрела обобщённый навык.

Репрезентативный контрольный диалог:
«Меня зовут Дима» → «У меня смартхаус на Home Assistant» →
подтвердить две предложенные связи → «Что у меня есть дома?» →
«Перечисли свои сущности» → отозвать связь владения →
повторить вопрос. Проверяй не только текст, но и
`retrieval_trace`, `source_fact_id`, счётчики,
`executed=false` и сохранность сырых записей.


## v0.5 — исследование поиска и долговременного диалогового протокола

Постановка: отделить улучшение ответа благодаря **внешнему поисковику**
от улучшения благодаря **сохранённым подтверждённым знаниям**. Qwen всё ещё
не дообучается: проверяется агентное использование инструментов и памяти.

Изоляция источников:
- `llm_only`: неизменённая модель без SQLite/поиска (базовая контрольная группа).
- `apprentice + web_mode=off`: Qwen + подтверждённая SQLite-память.
- `apprentice + web_mode=ask|auto`: тот же контекст + поиск через SearXNG,
  чтение ограниченного числа HTTPS-страниц и второй локальный вызов Qwen.
- `apprentice + external_context`: вручную импортированный ответ
  Google AI Mode. Он **не считается независимой проверкой** и не является
  подтвердённой учителем карточкой.

**Граница доверия:** текст сайта, поисковый snippet и вставленный ответ
Google AI не являются инструкциями, доказательствами доступа к устройствам
или основанием для сохранения сущности/способности. Из поиска нельзя
автоматически сделать `world_fact`. API для общего HTTP, shell и HA не
добавлялись. Веб-инструмент способен обращаться только к настроенному
SearXNG и публичным HTTPS-адресам из результатов; локальные IP, нестандартные
порты и редиректы не используются. Чтение страниц ограничено размером,
временем и числом запросов. DNS-проверка снижает риск SSRF, но не является
абсолютной защитой от DNS rebinding — не делай эту систему публичным
многопользовательским веб-краулером без дополнительной изоляции сети.

**Наблюдаемость:** `research_sessions`, `research_turns`,
`research_events` сохраняют режим, профиль, модель, длительность,
токены, фактический маршрут, предоставленные источники, решения учителя
и результаты ошибок. `research_web_searches` хранит запрос и статус.
JSON/Markdown — экспорт наблюдений, а не снимок весов модели.
Исходный `world_entities/world_facts` не заменяется этим журналом.

Сравнивай заранее зафиксированный набор вопросов (несколько парафраз),
с одинаковыми версией модели, профилем и условиями запуска.
После этапа `search+teacher confirm` повторяй задачи с отключённым
интернетом: только тогда можно измерить выигрыш от памяти.
Сохраняй отдельно точность ответа, обоснованность ссылок, долю ошибочных
обобщений, число переходов к источникам, задержку, токены и степень
вмешательства учителя. Без такой абляции успех Google AI или SearXNG
не доказывает обучения JARVIS.

## Что реализовано

- Независимый Qwen-сервис в Ollama. Веса не меняются, диалоговая модель
  не читает базу SQLite непосредственно.
- Универсальный анализатор пользовательской реплики без заранее заданной
  предметной области. Извлечение: `entity`, `action`, `fact`, `lesson`,
  `capability` (последнее — только гипотеза).
- Обязательная проверка человеком каждой предлагаемой записи. Учитель может
  исправить название и описание, отвергнуть или подтвердить. Сохраняется
  исходное сообщение, тип и время подтверждения.
- Обучаемая память в отдельных таблицах SQLite и поиск известных объектов
  через перекрытие слов и нечёткое текстовое сходство.
- Подтверждённые уроки с шагами/примерами вновь подаются в контекст Qwen.
- Оценки ответов учителем сохраняются в `apprentice_grades`, но не используются
  как автоматическое обучение. Для исправления ответа учитель должен
  объяснить правильный принцип и подтвердить новую карточку урока.
- Старые LLM-only и Hybrid режимы доступны для сравнительных экспериментов.

**Отсутствует:** обучение параметров, работающий исполнитель программ,
HTTP-клиент для произвольных серверов, реальные действия в HA, автоматическая
проверка корректности навыков. База знаний — не исполняющая среда.
Сохранённый "HTTP API" является текстовым уроком, а не доступом в сеть.

## Исследовательские риски

1. Qwen2.5:3b может ошибаться при структурированном извлечении и
   смешивать гипотезы с пользовательскими утверждениями.
2. Подтверждение человека относится к карточке, но не делает
   инструкцию корректной для всех будущих задач.
3. Текстовая нормализация и поиск по лексическому сходству не гарантируют
   переноса морфологии, контекста и синонимов на все формулировки.
4. Хранение примеров алгоритма не меняет навыков рассуждения Qwen.
5. При переполнении контекста материал может не попасть в запрос.
6. Учитель может отозвать подтверждение кнопкой «Забыть», но журнал обучения остаётся в базе; не вводи
   секреты и персональные данные в обучающие сообщения.
7. Не оценивай качество только по исходному обучающему примеру:
   это запоминание, а не обобщение.

## Минимальный эксперимент

Выбрать заранее неизвестную предметную область (например, игрушечный API)
и четыре набора раздельных примеров: `teach`, `paraphrase`, `transfer`,
`unrelated`. Обязательно сохранить тестовые запросы до обучения, чтобы
исключить подгонку. Создать сопоставимые условия:

- A: Qwen без внешнего контекста (LLM-only).
- B: Qwen с полностью описанными вручную инструментами/инструкциями.
- C: Apprentice с диалоговым обучением, подтверждениями и памятью.

Для каждой группы измерить успешность *проверяемых* задач, долю
необоснованных действий/заявлений, качество отказов и потребность в
уточнениях. Для каждого успешного решения фиксировать общее число
потраченных токенов, медианную задержку, число сообщений учителя,
сколько карточек он исправил и сколько новых формулировок распознано.

Сохранить одинаковую версию Qwen, температуру и условия запуска.
Отдельно проверять "рецепт голубцов" или другой общий вопрос до и после
обучения, чтобы обнаружить ухудшение общих способностей.

Только после этого сравнивать с работами по agent memory, skill
acquisition, interactive tool discovery и continual learning. Само
сочетание диалога с SQLite/RAG научной новизны не доказывает.

## Безопасность

Потенциальное действие из памяти — только описание. Ни предложение модели,
ни подтверждение карточки не даёт выполнения shell-команды, HTTP-запроса или
физического действия. Реальный исполнитель в будущем должен требовать
отдельного разрешения пользователя, явно ограниченных параметров,
проверки допустимости, журналирования и подтверждения опасных операций.


### Воспроизводимый regression-бенчмарк уровня retrieval

Команда из корня проекта:

```bash
python -m evaluation.graph_benchmark --dataset evaluation/graph_cases.jsonl --assert-pass
```

Фиксированный `evaluation/graph_cases.jsonl` проходит через отдельную
временную SQLite БД на каждый пример: *до обучения → кандидат ожидает
проверки → подтверждён → отозван*. Проверяется, что ответы на
перефразированные запросы о владении появляются **только после
подтверждения** и исчезают после отзыва. Метрики перечисляют ложные
срабатывания до подтверждения и после отзыва, а также долю успешных
ответов на контрольные запросы. Бенчмарк не вызывает Qwen и не является
доказательством переноса языковых навыков — это тест корректности
графа/поиска/сохранения доказательств. CI запускает его после unit-тестов.
