# Google Gemini в JARVIS: запуск и границы

## Что реализовано

- Qwen / Ollama остаётся локальным для обычного разговора и понимания команд.
- Для явного **публичного** запроса «поищи в интернете ...» JARVIS может
  обращаться прямо к Gemini API с инструментом Google Search Grounding.
  Ответ Gemini не пересказывается второй раз через Qwen.
- Для обычного публичного рецепта, которого нет среди подтверждённых знаний,
  используется та же ветка поиска.
- Если локальная Qwen явно признала отсутствие ответа или зациклилась,
  JARVIS может попытаться получить публичный ответ через Gemini.
- В запрос к Gemini **не передаются** SQLite, история чата, actor_id,
  данные HA и содержимое устройств. Передаётся только текст публичного
  вопроса (до 240 символов). Консервативный локальный фильтр пытается
  остановить случайные персональные данные. Он не заменяет полноценную DLP.
- Ответ Gemini хранится в журнале как эпизод, **не превращается автоматически**
  в подтверждённое знание. Избирательная память рецептов — отдельная задача.
- Запросы на физические действия по-прежнему нельзя исполнить через Gemini.
- Нет фонового агента, планировщика, анализа документов и интеграции с HA.

## Настройка (вручную на машине, где запущен docker compose)

1. Получи ключ в https://aistudio.google.com/apikey . **Не отправляй его в чат
   и не коммить в Git.** Тариф, квоты и доступные модели зависят от проекта.
2. Добавь или отредактируй локальный файл `.env` в каталоге compose:

   ```dotenv
   GEMINI_ENABLED=true
   GEMINI_API_KEY=СКОПИРУЙ_СВОЙ_КЛЮЧ_ЗДЕСЬ
   GEMINI_MODEL=gemini-2.5-flash-lite
   GEMINI_TIMEOUT=50
   ```

   Для защиты приватной информации оставь `GEMINI_ENABLED=false`, если
   не хочешь отправлять запросы в облако. В бесплатном тарифе Google может
   использовать данные для улучшения продуктов.
3. Обнови образы и сервисы **без удаления томов**:

   ```powershell
   git switch llm-index
   git pull --ff-only origin llm-index
   docker compose pull
   docker compose up -d --remove-orphans
   ```

4. Проверь наличие подключения, не раскрывая ключ:

   ```powershell
   docker compose exec llm python -c "from services.llm.gemini import configured; print('Gemini configured:', configured())"
   ```

5. В обычном режиме JARVIS с доступным интернетом проверь:
   «поищи в интернете рецепт котлет». В экспорте разговора должны появиться
   маршрут `gemini_google_grounded`, модель Gemini и ссылки на реальные
   источники. Если поставщик не вернул `groundingChunks`, JARVIS не
   назовёт результат проверенным поиском.

## Ошибки и fallback

- Нет ключа: Gemini выключен до локальной настройки; прежний путь
  SearXNG остаётся доступен.
- Gemini включён, но отказал по ключу, модели или квоте: JARVIS сообщает
  об ошибке. Он **не подменяет неудавшийся поиск выдуманным ответом Qwen**.
- Личные запросы, домашние адреса, имена, IP-адреса, пароли и некоторые
  устройства фильтруются до выхода к Google. Если фильтр сработал, нужен
  обезличенный публичный запрос.
- `web_mode=off` по-прежнему означает отсутствие интернет-запросов.
- Бесплатный Search Grounding для Gemini 2.5 Flash-Lite по документации
  Google ограничен (сейчас до 500 запросов/день). На новом проекте
  выбранная модель может быть недоступна, тогда посмотри список моделей
  и квоты в своём AI Studio. Модели Gemini 3+ могут иметь другие
  условия бесплатного Grounding.

## Что проверено

Автоматические тесты используют синтетические ответы Gemini и проверяют
формат Google Search, запрет передачи памяти, проверку источников и
маршрутизацию. **Проверка с живым Google API и твоим ключом возможна
только после локальной настройки.** CI не доказывает, что Gemini заработал
в развёрнутом JARVIS.
