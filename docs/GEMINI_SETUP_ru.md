# Gemini в JARVIS: бесплатные ответы и публичный поиск

## Теперь две независимые возможности

1. **Gemini — только резервная генерация**. JARVIS сначала проверяет
   подтверждённую SQLite-память, ранее выполненные публичные исследования и
   запускает локальную Qwen. Если Qwen явно не смогла ответить или
   зациклилась, JARVIS может обратиться к Gemini с **публичным** вопросом.
   Используется `generateContent` без инструмента `google_search`.
   У владельца проекта ответ `HTTP 200 / ANSWER: OK` реально получен
   от `gemini-3.5-flash-lite` без Google Search. Квоты могут меняться.
2. **Бесплатный поиск — SearXNG**. В режиме `auto` явная просьба «поищи
   в интернете рецепт котлет» сначала отправляется в SearXNG. Из найденных
   публичных страниц или поисковых фрагментов формируются ограниченные
   источники [1]–[5]. **Сначала локальная Qwen** анализирует источники.
   Если она не справилась, Gemini без Google Search Grounding анализирует
   только ограниченные публичные источники как резерв.
3. В режиме `ask` JARVIS **сначала запрашивает подтверждение поиска**
   (посредством сессионной операции). Наличие Gemini больше не обходит
   разрешение на поиск. `off` запрещает **поиск**, но не самостоятельный
   вызов явно включённого облачного Gemini для публичного вопроса.

## Границы и безопасность

- В Gemini не отправляются SQLite, история разговора, `actor_id`,
  личные предпочтения, данные Home Assistant и состояние устройств.
  Только текст публичного вопроса (не более 1200 символов) либо тот же
  вопрос и публичные результаты SearXNG (до пяти ограниченных выдержек).
- Консервативный локальный фильтр блокирует некоторые персональные
  имена, личные обращения, адреса, токены, IP, устройства и URL.
  **Это не полноценная DLP**: не вводи секреты в публичные вопросы.
- Gemini не может запускать действия и управлять HA. Проверки операций
  и разрешений выполняются отдельно локальным кодом. Информация из
  внешних источников не становится подтверждённым знанием автоматически.
- Вызовы Gemini отправляются в Google. Если ты не согласен с обработкой
  публичных запросов Google (включая условия Free Tier), оставь
  `GEMINI_ENABLED=false`. Для полностью локального режима Gemini
  отключается именно этой настройкой, а не переключателем поиска.

## Настройка на Windows + Docker Compose

В каталоге проекта `articles` проверь локальный файл `.env`:

```dotenv
GEMINI_ENABLED=true
GEMINI_API_KEY=твой_реальный_ключ
GEMINI_MODEL=gemini-3.5-flash-lite
GEMINI_TIMEOUT=50
WEB_SEARCH_ENABLED=true
```

Не добавляй ключ в Windows глобально, не вставляй его в исходники или Git.
Docker Compose передаст значения в контейнер `llm`. Оставь `.env`
вне контроля версий.

После получения новой версии:

```powershell
git switch llm-index
git pull --ff-only origin llm-index
docker compose pull llm gateway research
docker compose up -d --force-recreate llm gateway research
```

В этом проекте `compose.yaml` использует готовые образы GHCR (`build:`
отсутствует). Перед `docker compose pull` дождись успешной публикации
образов в GitHub Actions; `--build` не собирает исходники этой конфигурации.
Для изменения `.env` недостаточно `docker compose restart`: контейнер
нужно пересоздать.

Диагностика **без раскрытия ключа**:

```powershell
docker compose exec llm python -c "from services.llm.gemini import configured; print('Gemini configured:', configured())"
docker compose exec llm python -c "from services.llm.gemini import DEFAULT_MODEL; print(DEFAULT_MODEL)"
```

Проверки в интерфейсе JARVIS:

- «Что такое Python?» — сначала SQLite и локальная Qwen. Gemini
  вызывается, только если Qwen явно не справилась.
- После однажды успешно найденного с помощью SearXNG рецепта
  «Дай рецепт котлет» — `route=memory_public_research`, `model=SQLite`,
  `tokens=0`; сохраняются исходные URL, сеть и Gemini не нужны.
- «Поищи в интернете рецепт котлет», `web_mode=auto` —
  SearXNG → Qwen, `route=apprentice_web_evidence`.
  Если Qwen не справится, Gemini → `route=gemini_searxng_evidence`.
  В обоих случаях остаются реальные источники и их статусы.
- Тот же запрос при `web_mode=ask` — сначала запрос разрешения. После
  его подтверждения выполняется тот же поиск и анализ.
- При ошибке Gemini `429` / тайм-ауте после отказа локальной Qwen
  JARVIS сообщает о проблеме; он не выдумывает подтверждённый ответ.
  Если SearXNG недоступен, JARVIS не придумывает результаты поиска.

## Почему не Google Search Grounding

Для пользовательского API-проекта были получены такие **реальные** ответы:

- `gemini-2.5-flash` и `gemini-2.5-flash-lite`: HTTP 404 на старую модель;
- `gemini-3.5-flash-lite`: HTTP 200 без поиска, HTTP 429 с `google_search`;
- `gemini-3.8-flash`: HTTP 429 с `google_search`;
  запрос без поиска однажды завершился по тайм-ауту.

Это не доказывает, что Google Search Grounding запрещён всем бесплатно, но
доказывает, что зависеть от него в данном развёртывании нельзя. В текущей
маршрутизации JARVIS **не отправляет** `tools: google_search`.
Этот режим остался лишь для явных диагностических API-запросов.

## Что проверяют тесты

Офлайновые тесты проверяют отсутствие `google_search` по умолчанию,
запрет передачи приватной памяти, отдельную маркировку источников,
разрешение поиска, ошибки квоты и резервный маршрут через Gemini.
Они не заменяют проверку Docker-развёртывания и реального Gemini API.
