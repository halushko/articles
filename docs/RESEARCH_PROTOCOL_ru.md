# Исследовательский протокол JARVIS 0.3.2

## Главная граница

**Готовая технология:** Qwen2.5:3b / Qwen3:4b (Ollama) и опционально BGE-M3. Их веса не изменяются. LLM не имеет доступа к исследовательской SQLite; baseline не знает историю коррекций. Эмбеддер — готовый и замороженный, если включён.

**Исследовательская подсистема:** инкрементальное накопление подтверждений, действующие ссылки при сохранении истории конфликтов, символьный online-ранжировщик, контролируемое воздержание, явные понятия и домены, полный журнал решений. **Сам по себе этот SGD-ранжировщик не является научной новизной**: это baseline для будущей собственной идеи. Не называй систему автономно обучающейся общей LLM.

Функциональная декомпозиция:

```
                    ┌───────────────────────┐
 запрос пользователя →│ gateway: выбор режима │
                    └──────────┬────────────┘
                     ┌─────────┴──────────┐
                     ▼                    ▼
              ┌─────────────┐       ┌──────────────┐
              │ research    │       │ llm          │
              │ SQLite      │       │ Qwen2.5 / 3  │
              │ exact+SGD   │       │ без SQLite   │
              │ BGE optional│       └──────┬───────┘
              └─────────────┘              ▼
                                       Ollama
```

Три внешних эксперимента: `llm_only` (не читает research вообще), `research_only` (не зовёт LLM), `hybrid` (команда → исследование, прочий вопрос → LLM, вопрос о памяти → SQLite). Абляции индекса: `exact`; `online` (exact + online SGD); `combined` (online + опциональная замороженная семантика). При `SEMANTIC_ENABLED=false` ветви `online` и `combined` эквивалентны — это **намеренно**, а не улучшение точности.

## Гипотезы (пока не результаты)

- H1: подтверждённые online-соответствия сохраняют корректность на повторной формулировке и устойчивость к последним явным исправлениям.
- H2: online-поиск увеличивает покрытие *новых* русских и украинских парафраз по сравнению с `exact`, при контролируемой частоте неверных автоматических решений.
- H3: контролируемое воздержание сокращает опасные неверные выборы, ценой дополнительных уточнений.
- H4: гибрид уменьшает число LLM-запросов и задержку на ранее освоенных командах без ухудшения точности выбора целевого устройства.

## Пререгистрация перед настоящим экспериментом

1. Зафиксировать модели (точные теги и дайджесты), `config/llm.json`, `config/research.json`, код (commit SHA), версии Docker, CPU/GPU, режим прогрева.
2. Собрать минимум 100 независимых размеченных команд RU/UK с комнатами, действиями, конфликтами, отрицанием и отсутствующими объектами. Отдельно — бытовые понятия вне HA.
3. Разделить обучение/тест по парафразам. Дополнительно провести строгий сплит по *семействам понятий* для проверки обобщения, а не запоминания близких дубликатов.
4. Сравнить `exact`, `online`, `combined`; для внешней LLM-базы сначала получить **единый структурированный выход** `{action,target_id,abstain}` и фиксированную таксономию устройств. Обычные чат-ответы LLM из веб-интерфейса не позволяют честно посчитать accuracy выбора устройства.
5. Метрики: точные попадания, ошибочные выборы, отказ/уточнение, доля покрытых фраз, p50/p95 end-to-end задержки, задержка индекса, токены/время LLM, число исправлений до восстановления после конфликта.
6. При последовательном обучении оценивать текущий пример **перед** раскрытием правильной метки; не считать запоминание тестовой метки за обобщение.
7. Не настраивать пороги по тестовой выборке. Предусмотреть несколько случайных порядков обучения и доверительные интервалы для будущего исследования.

## Вклад vs ограничения

`online_weights` — стандартные разреженные признаки слов/символов, нормализованные и дополненные при новом соответствии и скорректированные при явном изменении; повторные подтверждения одной фразы не умножают вес. Вектор BGE-M3 **не дообучается**. База хранит доказательства (evidence) отдельно от активных (active_mappings). При конфликте актуальная связь меняется, но старые свидетельства остаются в истории и учитываются в аудите. Для нераспознанной новой фразы нет тихого автообучения: обучение только через явно подтверждённое `/learn`.

**Ограничения:** нет опубликованного результата, доказанной новизны, глубокого continual learning, автоматического открытия концептов, реального управления HA, голоса и полноценного planner. Правила RU/UK намеренно ограничены командами света; расширение грамматики — отдельный эксперимент. SQLite в эксперименте можно наполнить персональными фразами, поэтому держать его локально.

## Как запустить игрушечный benchmark

```
python -m evaluation.benchmark --dataset evaluation/toy_cases.jsonl --output toy_report.json
```

В Docker:

```
docker compose exec research python -m evaluation.benchmark --dataset evaluation/toy_cases.jsonl
```

Сейчас это **шесть обучающих + шесть тестовых синтетических примеров**, не научное доказательство. Вывод содержит prediction для каждого теста, `wrong`, `correct`, `abstained`, `safety_blocks` и медианное время индекса. Не трактовать `accuracy` только по выбранным ответам как общую точность — отдельно показывать воздержание.

## Следующий этап собственной идеи

Внутри `services/research/` можно заменить или расширить online scoring, а также построить иной экспериментальный индекс понятий. Контракт `resolve(text,ablation)` возвращает `status/route/target_id/candidates/latency_ms`; LLM-сервис не должен меняться. Параметры индекса лежат только в `config/research.json`. При каждой новой стратегии добавляй новый режим абляции, а не переписывай baseline — иначе нельзя честно измерить выигрыш.
