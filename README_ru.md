# JARVIS v0.6 — обучаемый мир, проверяемые изменения и наблюдаемость



## JARVIS v0.6 — изменения памяти, статус ответа, нормальная озвучка

Ранее модель говорила «Я переименован в Домик», но SQLite продолжала
отвечать «Меня зовут JARVIS». Оценка ответа как верного также ошибочно
воспринималась как обучение. Теперь **изменение знаний является отдельной
проверяемой операцией**.

- «Переименуй себя в Домик» создаёт **ожидающее подтверждения изменение**
  существующего имени assistant, но не меняет его сразу и не создаёт новую
  сущность `Домик`.
- «Переименуй Барсик в Рыжик» работает с **подтверждённой сущностью**:
  определяет однозначный `world_entities.id`, сохраняет прежнее имя как
  псевдоним и сохраняет ID сущности и графового узла.
- После «✓ Применить изменение» значение меняется в SQLite в транзакции
  с проверкой прежнего значения. Старые/конфликтные предложения не могут
  молча перезаписать новое имя. «✕ Отклонить» ничего не меняет.
- Вкладка «Изменения существующих знаний» показывает ожидающие операции;
  история операций хранится в `knowledge_changes` и
  `knowledge_change_events`. История диалога записывает подтверждение.
- Повторное «Почему ты продолжаешь говорить старое имя?» теперь позволяет
  объяснить состояние непроведённого изменения вместо противоречащих ответов.
- Правильность ответа **не является** разрешением на изменение памяти.
  Из Qwen тоже можно получить предложение обновить существующий объект,
  но только при явной просьбе учителя, с проверкой существующей цели и
  нового имени из текста. Никаких внешних действий это не включает.

### Наблюдаемый статус запроса

Над чатом отображается фактический этап сервера:
`routing` → `memory` → `planning` → `web_fetch` →
`web_answer` → `saving` → `done`. Если этап длится
больше 40 секунд, показано предупреждение. Таймер не является
процентом готовности или видимостью приватных мыслей модели.
Нельзя надёжно знать, «зависла» ли Qwen внутри одного блокирующего
запроса Ollama, но теперь видны этап и время ожидания. Статус
опрашивается по `GET /api/chat/status/{request_id}`.

### Читабельное озвучивание

Отображаемый ответ и Markdown/JSON экспорт остаются **без изменений**.
Перед отправкой в браузерный TTS отдельно обрабатывается копия:
Markdown-разметка, backticks, номера цитат и URL не читаются как
пунктуация; большие блоки кода не диктуются, заменяются коротким
«Пример кода показан на экране». Таблицы пропускаются с пояснением.
Распространённые аббревиатуры API, REST, URL, JSON произносятся словами.
Кнопка «🔊 Повторить» использует ту же подготовку.

### Проверка изменений

```text
Переименуй себя в Домик
→ предложение #... (НЕ применено)
Как тебя зовут
→ Меня зовут JARVIS.
[подтверди изменение]
Как тебя зовут
→ Меня зовут Домик.
```

Проверь тот же сценарий с произвольной ранее подтверждённой
сущностью. При поиске с Qwen 3b интерфейс может показать ожидание
в десятки секунд — теперь это видно явно. Перезагрузи страницу
через Ctrl+F5 после обычного `docker compose pull && docker compose up -d`
без удаления томов.

## JARVIS v0.5 — бесплатный поиск, журнал диалогов и эксперимент с Google AI

**Что добавлено:** поисковый движок SearXNG в отдельном Docker-контейнере
(публичный порт не открывается), чтение до 2 публичных HTTPS-страниц на запрос
и анализ до 4 результатов локальной Qwen. Платный API и ключи Google/Gemini
не требуются. Поисковые запросы отправляются внешним поисковикам,
используемым SearXNG, **только после разрешения в режиме «Спросить»**
или при явно включённом «Автопоиске».

**Режимы поиска в UI:** «🚫 Без интернета», «🔎 Спросить разрешение»
(по умолчанию), «🌐 Автопоиск». JARVIS может сам предложить запрос по
актуальному вопросу или документации; при разрешении gateway обращается к
SearXNG и передаёт Qwen цитируемые фрагменты, а не готовые подтверждённые
знания. Источники в ответе маркируются [1], [2] и отображаются под ответом.
Страницы, которые не удалось прочитать, имеют статус `search_snippet`,
`fetch_failed` и т. п. Если поиск недоступен, система сообщает об ошибке,
а не выдумывает результаты. Базовые режимы v0.3 и LLM-only **не получают
web tools**, чтобы не портить контрольную группу.

**Бесплатный Google AI Mode:** кнопка открывает
`https://www.google.com/search?udm=50&q=...` в твоём браузере.
Google AI Mode — не API: Chrome/Google аккаунт обрабатывает запрос внутри
пользовательской сессии. Скопируй ответ в поле «Ответ Google AI»;
он сохранится в журнале как **непроверенный внешний материал**, после чего
Qwen сможет его разобрать. Нет автоматического получения результата или
обхода ограничений Google.

**Журнал:** создаётся SQLite-сессия с UUID и записью каждого завершённого
вопроса/ответа, времени, модели, режима, токенов, маршрута, поискового запроса
и источников. Есть выбор старого диалога, «Новый», оценка ответа и события
подтверждения/отзыва гипотез. Экспорт текущей сессии в **Markdown** и **JSON**
доступен кнопками рядом с чатом. Обновление страницы не стирает
сохранённые сообщения. Данные остаются в прежнем volume `research_data`.
Предыдущие разговоры, которые ещё не записывались в SQLite, восстановить
нельзя. Не передавай пароли/токены в чат: экспорт включает тексты сообщений.

### Обновление установленного JARVIS (PowerShell в каталоге проекта)

```powershell
git switch llm-index
git pull --ff-only origin llm-index
docker compose pull
docker compose up -d --remove-orphans
```

Не выполняй `docker compose down -v`: это уничтожит SQLite и модели Ollama.
После обновления браузера нажми Ctrl+F5. Сервис SearXNG и конфигурация
JSON API уже включены в Docker-образ
`ghcr.io/halushko/articles-llm-index-searxng:latest`.
Если используешь `.env`, можешь добавить
`WEB_SEARCH_ENABLED=true` и непустой `SEARXNG_SECRET`, но для
локального запуска значения по умолчанию уже заданы.
Если SearXNG недоступен (например, поиск заблокирован поисковыми
провайдерами), история и LLM продолжают работать, а ошибка поиска
явно показывается.

**Проверка:** введи «Найди официальную документацию Python» и разреши
предложенный поиск. Проверь реальные ссылки и статусы источников,
затем нажми «Скачать диалог .md» и «Экспорт JSON», обнови страницу
и открой сессию из истории. Повтори тот же вопрос в LLM-only:
тогда поиск и память не вызываются (контрольный сценарий).

## v0.4.2: общая подтверждённая память и граф отношений

**Исправлено:** ранее можно было подтвердить пять сущностей в SQLite,
но получить от Джарвиса «я не храню сущности». Это происходило потому, что
в режимах `llm_only` и старом `research_only` не было общего механизма
обращения к Apprentice. Теперь:

- «Ученик»: ответы на узкие вопросы о памяти («Перечисли сущности»,
  «Что у меня есть дома?», «Какие связи подтверждены?») идут из SQLite
  с учётом ролей и реальных подтверждений. Остальные вопросы Qwen
  получает с релевантным подграфом из SQLite.
- Старые Hybrid и Research-only: инспекция подтверждённой памяти тоже
  доступна, но маршруты старых экспериментальных команд не изменены.
- **«Только LLM · контроль БЕЗ памяти»**: намеренно ничего не читает
  из SQLite. Это условие сравнения — не режим общения с обученным учеником.
  В интерфейсе об этом теперь предупреждение.

Появилась **проекция подтверждённого графа** из старых `world_entities`
и `world_facts` в `graph_nodes` и `graph_edges`. Один и тот же
нормализованный термин, подтверждённый в разных доменах, получает один
канонический ID. Все старые записи и история сохраняются; в UI сырые
подтверждения доступны под раскрывающимся списком с кнопками отзыва.
Узел может появиться из подтверждённого отношения, даже если его ещё
не выделяли отдельной карточкой сущности. Разные написания одной сущности
(например, «Джарвис» и «JARVIS») можно **объединить вручную** в панели
«Объединить разные написания». Такая связь хранится в `graph_equivalences`,
отображается в графе, отменяется без удаления исходных записей и
пишется в журнал. Система **не делает автоматическую склейку
омонимов**: учитель должен подтвердить, что это действительно один объект.

**Учебные связи:** если сказать «У меня есть X» или
«У меня X на Y», простой открытый грамматический анализатор предложит
подтвердить `user — имеет → X` и, при наличии Y, `X — на → Y`.
Qwen продолжает предлагать свои гипотезы. Ни один факт не записывается
как истинный до нажатия «Подтвердить»; тройку можно исправить через
«Изменить» (субъект, предикат, объект). Например, если хочешь учить
соответствие «смартхаус использует Home Assistant», исправь «на» на
«использует» перед подтверждением.

Для проверки: «Меня зовут Дима» → «У меня смартхаус на Home Assistant» →
подтверди связи → «Что у меня есть дома?» → «Перечисли мои сущности» →
«Какие связи ты знаешь?». Ответы показывают маршрут и источник
`confirmed_sqlite_graph`. Никакого Home Assistant-доступа от этой
проекции не появляется. Экспериментальная методика и ограничения —
в `docs/APPRENTICE_PROTOCOL_ru.md`.

## Память участников, словарь распознавания и реальные возможности

Начиная с этого обновления Джарвис хранит имена участников **отдельно** от
обычных сущностей: `assistant=JARVIS` задаётся приложением, имя `user`
обновляется после явной фразы вроде «Меня зовут Дима».
Если ранее пользователь подтвердил своё имя как сущность вместе с такой
фразой, миграция восстановит имя без сброса истории. Вопросы
«Как меня зовут?» и «Как тебя зовут?» обслуживаются непосредственно SQLite,
**без вызова Qwen** и без карточек новых знаний. Если имя неизвестно,
Джарвис спросит его. Это убирает случайную путаницу в этих вопросах.

Новые таблицы SQLite: `dialogue_roles`, `speech_corrections`,
`runtime_capabilities`. Словарь произношений обучается как через форму
в интерфейсе, так и фразой
«Когда я говорю «хомо сестранте», я имею в виду Home Assistant».
Словарная коррекция применяется к тексту **после** браузерного STT,
но **до** индекса и Qwen; сам движок распознавания браузера не обучается.
Замена отображается отдельной строкой в диалоге. Словарь поддерживает
редактирование через повторное сохранение и удаление. Не используй
для токенов, паролей или секретных данных.

Реестр возможностей в интерфейсе показывает проверенные функции:
чтение знаний и создание предложений доступны; подтверждение — только
учителю; HTTP-запросы, выполнение кода и действия в других системах
**отсутствуют**. Предложение модели о новом навыке ничего не разблокирует.
Для запросов на внешнее подключение без доступного HTTP-инструмента
Джарвис сообщает о конкретном ограничении, вместо выдуманной попытки
подключения или просьбы отправить токен. Ни одна из этих функций не
даёт Home Assistant доступ или внешний сетевой вызов.

Поле чата теперь многострочное: **Enter отправляет**, **Shift+Enter
вставляет перенос строки**. Диктовка работает с тем же полем.
В некоторых случаях простые вопросы об именах и доступных
инструментах отвечаются без затрат 10–20 секунд на генерацию.
Для других вопросов скорость по-прежнему зависит от Qwen и оборудования.

API: `POST /api/apprentice/speech-corrections`
(`{"heard":"хомо сестранте","correct":"Home Assistant"}`) и
`POST /api/apprentice/speech-corrections/delete` (`{"item_id":1}`).
`GET /api/apprentice/state` возвращает также `dialogue`, а
`POST /api/apprentice/context` включает нормализованный текст,
участников и проверенный реестр возможностей.

## Голос: диктовка с паузами и голосовые ответы

🎤 начинает диктовку, **⏹ вручную завершает её и отправляет сообщение**.
Короткая пауза не считается концом команды. Если браузер завершит
сегмент распознавания, интерфейс попытается начать следующий, сохранив
предыдущие слова. Кнопка «Отправить» работает и без диктовки.
При сбое распознавания черновик остаётся в поле ввода.

«🔊 Озвучивать ответы» включено по умолчанию, настройка сохраняется.
Для повторного чтения есть «🔊 Повторить». Перед новым голосовым вводом
JARVIS прекращает озвучивание. RU/UA переключает язык распознавания
и озвучивания; список голосов зависит от ОС и браузера.

Распознавание и синтез реализованы Web Speech API браузера.
В Chrome/Edge распознавание может использовать внешние серверы.
Это пока не полностью локальные STT/TTS. Если браузер заблокирует
перезапуск после паузы, уже распознанный текст можно отправить вручную.



**Новый режим: «Ученик · свободное обучение».** Открывай интерфейс, пиши на обычном
языке о новом устройстве, системе, понятии или алгоритме. JARVIS использует
Qwen для понимания речи, **сам предлагает** сущности, действия, связи, уроки и
гипотезы будущих навыков. Ты проверяешь карточки «Подтвердить / Изменить /
Отклонить». Только подтверждённые записи доступны в будущих диалогах.
Кнопки «Верно / Ошибка» фиксируют оценки учителя отдельно от знаний:
оценка **не** изменяет веса Qwen и сама по себе не записывает правильное решение.
Это не специализация на HA: никаких домашних устройств или уроков
программирования в модель мира заранее не заложено.

**Это не самообучение весов и не автономный программист.** Модель не обучается
новым нейронным навыкам; она получает проверяемую внешнюю память. Подтверждённое
описание HTTP-запроса не даёт права делать HTTP-запрос. Код и команды не
исполняются. Home Assistant пока **не подключён**; токен HA не нужен и его
нельзя вводить в JARVIS. Гипотезы о новых возможностях не означают, что
Джарвис действительно ими обладает.


## Как проверить обучение

Поговори с Джарвисом без формы для ручного создания сущности:

1. «У меня есть аккумулятор по имени Мелкий. Он в гараже».
2. JARVIS предложит карточку сущности и, возможно, идеи действий.
   Проверь названия и описание, **подтверди**. Ошибочное подтверждение можно затем отозвать кнопкой «Забыть». Исправления сохраняют правку учителя.
3. «А кто такой Мелкого?» — попробуй альтернативное написание.
4. «Я учу тебя сортировке: сравнивай соседние элементы, меняй местами и
   повторяй до упорядочивания. Пример: [3,1,2] → [1,2,3]».
5. Подтверди карточку урока, затем спроси: «Как отсортировать [4,1,3]?»
6. Спроси «Что ты знаешь из того, чему я тебя научил?» и открой «Показать все знания».

Сохранённые знания — только то, что подтвердил человек. Новые формулировки и
перенос знаний проверяются в диалоге, **не гарантируются**. Маленькая Qwen
может не выделить сущность, предложить неверные отношения или ошибиться
при применении урока; карточки нужно проверять.

## Структура обучения

`research` мигрирует существующую SQLite БД и добавляет:
`apprentice_proposals` (предложения и статусы), `world_entities`,
`world_aliases`, `world_actions` (описания, executor=NULL),
`world_facts` (тройки), `world_lessons` (алгоритмы, шаги, примеры),
`capability_ideas` (потенциальные умения), `apprentice_events` (аудит).
Это отдельные таблицы и отдельные API, старые таблицы не трогаются.

`gateway` запрашивает подтверждённые знания у `research`, передаёт их в
`llm /analyze` вместе с текущим сообщением и короткой историей. Для любого
предмета используется **одна универсальная инструкция**, а не
зашитые заранее команды дома или уроки Python. Qwen возвращает структурированные
кандидаты; `research` сохраняет их как неподтверждённые. После подтверждения
они используются в контексте будущих запросов. У LLM-сервиса по-прежнему
**нет прямого доступа к SQLite**.

```text
GET  /api/apprentice/state
POST /api/apprentice/grade {"question":"...","answer":"...","rating":"good|bad","teacher_note":"..."}
POST /api/apprentice/forget {"kind":"entity|action|fact|lesson|capability","item_id":1}
POST /api/apprentice/review {"proposal_id":1,"decision":"confirm|reject",
                             "name":"необязательно","description":"необязательно"}
POST /api/chat {"text":"У меня есть устройство X",
                "experiment":"apprentice","profile":"fast|deep"}
```

Старые режимы `hybrid`, `research_only`, `llm_only`, тесты v0.3.2 и
экспериментальный индекс остаются для сравнения. См.

# Архив v0.3.2 — отделённая LLM и исследовательская индексация

Разработка ведётся **в ветке `llm-index` репозитория `halushko/articles`**. `master` не трогаем.

## Принцип разработки и развёртывания

Любое изменение коммитится в `llm-index` → GitHub Actions прогоняет тесты → публикует три контейнера в GHCR. **На Windows не нужен исходный код Python, локальная сборка, `git pull` или копирование файлов**. После зелёного workflow достаточно в папке с неизменным `compose.yaml` выполнить:

```powershell
docker compose down
docker compose pull
docker compose up -d
```

`down` **не** удаляет volumes. Не используй `down -v`: он удалит индекс и скачанные модели. `pull` скачивает обновлённые образы, `up -d` запускает их. После коммита **подожди завершения публикации всех трёх образов**: если сделать `pull` во время workflow, можно получить разные версии сервисов.

**Важный нюанс:** изменения в `compose.yaml` и `.env.example` не подтягиваются командой `docker compose pull`: это локальные файлы. Мы считаем их стабильным контрактом, изменения алгоритмов и настроек LLM/Research храним в образах. Если когда-нибудь придётся менять Compose, это отдельное миграционное обновление, а не обычный down-pull-up.

## Первый запуск (один раз)

```powershell
git clone --branch llm-index --single-branch https://github.com/halushko/articles.git jarvis-llm-index
cd jarvis-llm-index
Copy-Item .env.example .env
docker compose pull
docker compose up -d
```

Открой `http://localhost:8766`. Старый v0.3.1 на порту 8765 не трогаем.

При первом запуске `model-init` **сам скачает** Qwen2.5:3b и Qwen3:4b в отдельный постоянный том. На следующих запусках уже скачанные модели не перекачиваются. Операция `docker compose up -d` может ожидать первоначальную загрузку. Для проверки:

```powershell
docker compose ps
docker compose logs --tail=60 gateway llm research model-init
```

Образы GHCR становятся доступны после успешного GitHub Actions workflow. Если возникнет `denied`, пакеты пока приватны — один раз открой настройки соответствующего GHCR package и включи Public или выполни `docker login ghcr.io` с токеном на чтение пакетов. **Ни пароли, ни токены не добавляй в репозиторий.**

## Независимые части

| Контейнер | Образ GHCR | Что меняем в GitHub | Данные |
|---|---|---|---|
| `llm` | `articles-llm-index-llm` | `services/llm/`, `config/llm.json` | Нет доступа к БД |
| `research` | `articles-llm-index-research` | `services/research/`, `config/research.json` | `research_data` (SQLite) |
| `gateway` | `articles-llm-index-gateway` | `services/gateway/`, `web/` | Нет |
| `ollama` | `ollama/ollama:0.40.17` | Закреплённая версия готового движка | `ollama_models` |

У контейнеров LLM и Research **разные Docker-образы, API и права доступа к данным**. Research не импортирует сервис чата, LLM не содержит исследовательского кода и базы.

`config/llm.json` задаёт профили `fast`/`deep`, модели, thinking, температуру и лимиты. `config/research.json` задаёт learning rate, пороги, допустимые ранжировщики и семантические параметры. **Меняем в репозитории, затем down-pull-up на локальной машине**, а не редактируем локальные конфиги.

Режимы через UI: `llm_only` (базовая LLM), `research_only` (свой индекс без чата), `hybrid` (индекс для известных команд, LLM для остального). Абляции индекса: `exact`, `online`, `combined` (опциональная замороженная BGE-M3). Смена режима в UI не требует перезапуска.

## API и исследование

```text
GET  /api/health
GET  /api/memory
GET  /api/targets
POST /api/chat {"text":"...", "experiment":"hybrid|research_only|llm_only", "profile":"fast|deep", "ablation":"exact|online|combined"}
POST /api/learn {"phrase":"Включи свет в туалете", "target_id":"light.lab_toilet"}
POST /api/concepts {"name":"Духовка", "domain":"техника", "kind":"устройство"}
POST /api/feedback {"decision_id":1, "rating":"good|bad"}
```

Публичный API только через `gateway` (localhost:8766), остальные контейнеры в приватной сети Compose. Реальные устройства Home Assistant **не управляются**, возвращается `executed: false`. Индекс и LLM независимы от старой v0.3.1. Голос и TTS не включены.

Для разработчика: тесты CI — `python -m unittest discover -s tests -v`, затем `python -m evaluation.benchmark --dataset evaluation/toy_cases.jsonl`. Методология и ограничения: `docs/RESEARCH_PROTOCOL_ru.md`.

## Научная честность

`research_only` не должен попадать в LLM при любой ошибке и не должен изображать знания, которых в базе нет. `llm_only` не должен видеть SQLite. Никакие изменения Qwen не считаются научным вкладом индекса. Сравнение делается на одном фиксированном наборе запросов с учётом отказов, времени и точности; ранжировщик v0.3.2 — пока **baseline**, а не доказанная новизна.

Для регрессионной проверки графа отдельно от Qwen: `python -m evaluation.graph_benchmark --dataset evaluation/graph_cases.jsonl --assert-pass`. Это тест SQLite retrieval и отзыва, а не доказательство обучения языковой модели.
